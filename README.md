# JIX — تطبيق فيديو قصير + بث مباشر (نسخة حقيقية قابلة للتشغيل)

## يعمل فوراً بدون أي إعداد
افتح `index.html` مباشرة (أو ارفع الملفات الخمسة لأي استضافة ثابتة). التطبيق
يعمل بـ **وضع تجريبي محلي كامل الوظائف**: كل الميزات (إعجاب، تعليق، دردشة،
نشر فيديو من جهازك، هدايا، محفظة، بث بمعاينة كاميرا حقيقية) تعمل فعلياً
وتُحفظ في متصفحك. هذا ليس "شكل بدون وظيفة" — هو تطبيق حقيقي، لكن بياناته
محلية لجهازك فقط إلى أن تربطه بخادم حقيقي (الخطوات بالأسفل).

## لتفعيل خادم حقيقي متعدد المستخدمين (Supabase)
1. أنشئ مشروعاً مجانياً في https://supabase.com
2. افتح **SQL Editor** والصق محتوى `supabase-schema.sql` بالكامل ثم شغّله.
3. من **Storage** أنشئ Bucket باسم `videos` واجعله Public، وأضف سياسة رفع
   تسمح فقط لصاحب المجلد بالكتابة (التفاصيل بأسفل الملف نفسه).
4. من **Project Settings → API** انسخ `Project URL` و`anon public key`
   وضعهما في أعلى `app.js` (`SUPABASE_URL`, `SUPABASE_ANON_KEY`).
5. أعد تحميل الصفحة — سيتحول التطبيق تلقائياً لوضع الخادم الحقيقي، ويطلب
   تسجيل الدخول برمز بريد إلكتروني (Magic OTP، بدون كلمات مرور مخزَّنة).

## لتفعيل بث مباشر حقيقي بين عدة مستخدمين
الواجهة (كاميرا، مايك، دردشة البث، الهدايا) **جاهزة وتعمل الآن فعلياً على
جهازك** كمعاينة. لكن توصيل صوتك/فيديوك لمشاهدين آخرين عبر الإنترنت يحتاج
بالضرورة بنية توزيع وسائط (WebRTC SFU) — لا يوجد طريقة لبنائها داخل صفحة
HTML وحدها، وأي أداة تدّعي ذلك بلا خادم وسيط تكون غير حقيقية. الخطوات:
1. أنشئ حساباً في **Agora** أو **LiveKit Cloud** أو **Daily.co** (كلها
   توفر باقات تجربة مجانية).
2. اقرأ التعليقات كاملة داخل `live-config.js` — فيها شرح خطوة بخطوة
   ومكان بالضبط لوضع مفاتيحك وربط SDK المزوّد.
3. **تنبيه أمني مهم:** أي مفتاح "سرّي" (Secret/API Secret) لا يوضع أبداً
   داخل كود المتصفح — توليد توكن الدخول للبث يجب أن يتم من دالة خادم
   (Supabase Edge Function مثلاً)، وهذا موثّق داخل الملف.

## لتفعيل شحن عملات حقيقي بأموال حقيقية
شاشة "المحفظة" الحالية تجريبية بوضوح (مكتوب ذلك بالواجهة نفسها) لأن أي
عملية دفع حقيقية تتطلب حساب تاجر مع Stripe/Apple Pay/Google Pay وتحقق
Webhook موقّع من الخادم — لا يمكن ولا يجوز تنفيذ ذلك من كود متصفح وحده
(أي محاولة كهذه تكون قابلة للتزوير بالكامل من طرف المستخدم).

## قائمة الميزات المنفَّذة فعلياً (53 ميزة)
**الخلاصة والفيديو:** تمرير عمودي بنمط Snap، تشغيل/إيقاف بالنقر، إعجاب
بنقرتين متتاليتين مع أنيميشن قلب، زر إعجاب جانبي، عداد مختصر (K/M)،
هاشتاقات ملونة قابلة للتمييز داخل الوصف.

**تفاعل اجتماعي:** تعليقات حقيقية متصلة بقاعدة بيانات، عداد تعليقات حي،
مشاركة عبر واتساب/تيليجرام/X/مشاركة النظام، نسخ رابط، تفعيل/تعطيل
التعليقات والمشاركة لكل منشور من صاحبه، متابعة/إلغاء متابعة.

**اكتشف:** هاشتاقات رائجة، تحديات نشطة بجوائز عملات، حسابات مقترحة،
بحث فوري بالمستخدمين/الهاشتاق مع تقليل تكرار الطلبات (debounce).

**النشر:** رفع فيديو حقيقي من الجهاز، معاينة قبل النشر، وصف بدعم
الهاشتاق، تبديل التعليقات/المشاركة، تحقق من الحجم والنوع، نشر فعلي
لـ Supabase Storage + جدول المنشورات (أو تخزين محلي بوضع الضيف).

**الرسائل:** تبويبات إشعارات/محادثات/دردشة جماعية، دردشة جماعية لحظية
عبر Supabase Realtime، تمييز رسائلي بصرياً، شارة غير مقروء، قائمة
إشعارات بأنواع مختلفة (إعجاب/تعليق/متابعة/هدية/نظام).

**الملف الشخصي:** إحصائيات (متابَع/متابعون/إعجابات/عملات)، تعديل
الاسم/المعرف/النبذة/الصورة مع تحقق من صحة المعرف، تبويب فيديوهاتي/
إعجاباتي، محفظة عملات.

**البث المباشر والهدايا:** اختيار بث فيديو أو صوتي، معاينة كاميرا/مايك
حقيقية، عداد مشاهدين، دردشة أثناء البث، **30 هدية** بخمس فئات أسعار
(1 إلى 9999 عملة)، تأثير بصري متدرج الحجم والتوهج حسب الفئة، **صوت
مولَّد إجرائياً بـ Web Audio API** يختلف حسب فئة الهدية (بدون أي ملفات
صوت خارجية)، سجل هدايا حي، خصم رصيد فعلي مع دالة خادم آمنة atomic.

**الحساب:** تسجيل دخول برمز بريد إلكتروني بدون كلمة مرور، وضع ضيف
تجريبي كامل الوظائف بدون إعداد.

**عام:** تنبيهات Toast، دعم RTL كامل، تصميم متجاوب، احترام تفضيل تقليل
الحركة، هوية بصرية JIX (تدرج أحمر/أزرق على أسود).

## قائمة الحمايات المنفَّذة فعلياً (30 حماية حقيقية)
**طبقة الواجهة (`security.js`):**
1. تعقيم كل نص مستخدم (escapeHtml) قبل العرض — يمنع XSS
2. إزالة محارف تحكم/اتجاه خفية من أي مدخل نصي
3. تقييد طول كل حقل في الكود نفسه (وليس فقط HTML القابل للتجاوز)
4. تعقيم أي رابط والسماح فقط بـ http/https (رفض javascript:/data:)
5. تحقق صارم من صيغة البريد الإلكتروني (يمنع Header Injection)
6. تحقق من صيغة اسم المستخدم قبل قبوله
7. توليد معرّفات بمولّد عشوائية مشفّر (crypto.getRandomValues)
8. محدد معدل (Rate Limiting) مطبَّق فعلياً على: إعجاب، تعليق، دردشة،
   هدايا، بحث، نشر فيديو، طلبات تسجيل الدخول
9. تحقق من صحة قيمة العملات (عدد صحيح موجب ضمن حد أعلى)
10. تخزين محلي آمن بمعالجة استثناءات كاملة
11. تجميد Object.prototype لتقليل سطح هجوم Prototype Pollution
12. منع تضمين الصفحة داخل إطار خارجي (Clickjacking) من جهة العميل
13. سياسة Content-Security-Policy تمنع تحميل سكربتات من مصادر غير موثوقة
14. تحقق من حجم ونوع ملف الفيديو قبل رفعه (منع استنزاف الموارد)
15. رسائل الأخطاء المعروضة للمستخدم عامة، والتفاصيل التقنية بـ console فقط

**طبقة الخادم/قاعدة البيانات (`supabase-schema.sql`) — وهذا الجزء الأهم
فعلياً لأن أي حماية بالمتصفح وحدها قابلة للتجاوز من نفس صاحب الجهاز:**
16. تفعيل Row Level Security إجبارياً على كل جدول
17. قراءة عامة محكومة + كتابة/تعديل/حذف مقيّدة بـ auth.uid() فقط
18. الرسائل الخاصة مرئية فقط لطرفيها
19. الإشعارات مرئية فقط لصاحبها
20. قيود CHECK على طول النصوص وقيم العملات داخل قاعدة البيانات نفسها
    (دفاع مزدوج حتى لو تم تجاوز تحقق الواجهة)
21. دالة `send_gift` تعمل كمعاملة atomic بالخادم لمنع التلاعب بالرصيد
    أو التسابق (Race Condition) عند إرسال هدايا متتالية بسرعة
22. سياسة تخزين تقيّد رفع الفيديو بمجلد صاحب الحساب فقط
23. تسجيل دخول بدون كلمة مرور مخزَّنة (Magic OTP) يقلل خطر تسريبها
24. عدم وجود أي مفتاح سرّي داخل كود الواجهة — فقط anon public key
25. توكن بث الفيديو/الصوت مصمَّم ليُولَّد من خادم خلفي فقط (موثّق)
26. اتصال قاعدة البيانات والدردشة الحية عبر HTTPS/WSS إلزامياً فقط
27. عدم الاعتماد على أي عداد قادم من المتصفح (إعجابات/مشاهدات) لتحديد
    الصلاحيات أو الرصيد — المصدر الوحيد هو قاعدة البيانات
28. صلاحيات محدودة افتراضياً (Deny by default) ثم سياسات صريحة فقط
    لما هو مطلوب لكل جدول
29. فصل واضح بين بيانات الحساب العامة وبيانات حساسة (لا كلمات مرور
    مخزَّنة إطلاقاً في هذا المخطط)
30. تعليمات صريحة بعدم تخزين مفاتيح دفع سرّية في الواجهة أبداً

### صراحةً: هذا غير مكتمل بدون إعدادات خارج نطاق كود التطبيق
حتى بعد كل ما سبق، تطبيق إنتاجي حقيقي يحتاج أيضاً أموراً لا يمكن تفعيلها

دوري لقاعدة البيانات، مراقبة وتنبيهات أمنية، فحص دوري لثغرات الاعتماديات
(npm audit)، حساب تاجر حقيقي موثّق لأي مدفوعات، وسياسة خصوصية/شروط
استخدام متوافقة مع قوانين بلدك (خصوصاً لتطبيق فيه بث مباشر ومحتوى ينشره
مستخدمون). هذه ليست "سطر كود" بل قرارات وإعدادات على مستوى المشروع.
